# Brief D08 — CRA Readiness Diagnostic (live, multi-respondent web app)

**Title (page `<title>`):** "CRA Readiness Diagnostic"
**Format:** a hand-built single-page HTML artifact published with the `Artifact` tool, with a **shared database** so many product teams can submit assessments and everyone sees the live portfolio view. Before writing any code: load the `artifact-design` skill and the `artifact-capabilities` skill (Skill tool) and follow them — the database capability (`db`) and its `window.claude.*` API are defined there. Call `Artifact` `action: "quickstart"` with intent "other" once first, as the tool requires. Write the file in `pack/out/diagnostic/index.html`. Icon: "chart" or "gauge".

**Why it matters:** this is the pack's showpiece tool. It must look and feel like a premium consulting product (think a McKinsey/BCG digital diagnostic), work flawlessly on desktop and phone, and turn answers into an instant, executive-grade portfolio heatmap.

**Data:** `pack/data/pack_data.json` → `diagnostic` (scale, 10 domains, 40 questions each with `basis`, `evidence`, `action`; `baseline_scores` for 13 families; target level 3) and `client.product_families` (id, name, BU, class, wave, route). Embed what you need in the page.

**Design:** use the brand tokens in BRIEF.md section 4 (Source Serif 4 / Inter / JetBrains Mono via Google Fonts; ink, paper, teal accent, RAG and maturity colours). Light and dark mode per the artifact-design contract. Clean, spacious, confident; no gimmicks.

**Features:**
1. **Landing / overview** — what the diagnostic measures (10 domains), the 0-4 scale with descriptors, the readiness index definition (mean of min(score,3)/3; 100% = every question at level 3), estimated time (12-15 minutes), and two entry points: "Assess a product" and "View portfolio".
2. **Assessment flow** — choose a product family from the list (or add a new one: name, BU, class), respondent role (free text) and optional name; then 10 domain steps with a progress indicator. Each question shows the statement, its legal basis (small, mono), a 0-4 segmented control with the level names, an expandable "What evidence counts" line (from `evidence`) and an optional evidence/notes field. Keyboard accessible. Autosave the in-progress draft per viewer (local, wrapped in try/catch) so a reload does not lose answers. Submit writes one record to the shared database: family id/name, BU, class, respondent role, optional name, answers {questionId: score}, notes, timestamp, `sample: false`.
3. **Product result view** (shown after submit and from the portfolio) — readiness index with a large number and a ring or bar; domain bars vs target 3 (or a radar if it stays legible); the five lowest-scoring questions turned into **priority actions** (use each question's `action` text) with the legal basis; a "copy summary" button.
4. **Portfolio view** — for each family the latest submission: heatmap families × domains (cells show the 0-4 average with one decimal on the maturity colour scale), readiness index column, BU and class tags, filters (BU, class, wave), sort by readiness; portfolio KPIs (portfolio index, families assessed, weakest domain, strongest domain); a domain-average bar chart; "ten weakest questions across the portfolio" list with actions; an insight line generated from the data (e.g. "Conformity & access is the weakest domain at 16%; Class I home products are least ready"). Export CSV of all latest submissions.
5. **Sample data** — pre-load the 13 illustrative baseline assessments (from `baseline_scores`, respondent role "Programme moderation", dated 28 Oct 2026, `sample: true`) so the portfolio view is populated on first open. Seed them only if the database has none (idempotent; guard against double seeding), or keep them embedded as a fallback layer that real submissions override per family. Label sample rows "Illustrative" and provide a toggle "Include illustrative sample data". With samples only, the portfolio index must show 44% and domain readiness: Governance 58%, Scope & class 45%, Risk & design 47%, SDLC & testing 56%, SBOM & supply chain 38%, Vulnerability handling 38%, Updates & support 48%, Art 14 reporting 72%, Documentation & DoC 24%, Conformity & access 16% — verify your computation reproduces these.
6. **About / method** — scale, scoring, domain-to-article mapping, data note (submissions are visible to everyone with the link; do not enter personal or confidential vulnerability details), version "v1.0 · facts as at 30 Oct 2026", white-label footer "Prepared by [Advisor] · Illustrative engagement: Example Group".

**Robustness:** handle empty database, network errors (show a calm retry message), concurrent submissions, very long notes, a family with multiple submissions (portfolio uses the latest; product view can show history). No external scripts beyond allowed CDNs (see the Artifact tool contract); charts can be hand-built SVG.

**Verify before reporting:** open the published page in the pre-installed Playwright Chromium (desktop 1440px and phone 390px) — screenshot overview, assessment step, product result and portfolio — check layout, numbers (44% etc.), dark mode, no console errors. Note: the database may not be reachable from a local file; test the data layer as far as possible and test the UI with the embedded sample layer. Report the URL, the capabilities declared, and how sample data is handled.
