1

Is it in scope?

Three cumulative conditions in Art 2(1), then the six sectoral carve-outs. Most products pass; the edge cases are SaaS, internal tools and non-monetised open source.

What are you placing on the market? Art 3(1)-(5)
Can it exchange data with a device or network, directly or indirectly? Art 2(1); guidance paras 26-28

Count reasonably foreseeable use. Software on a networked computer is indirectly connected. A signal that only switches or powers something is not a data connection.

How is it supplied in the EU? Art 3(21)-(22); Art 4

The test is whether that act applies to this product, not whether it looks medical or automotive.

2

What is its core functionality?

A product is in a category only when its core functionality matches the technical description in Implementing Regulation (EU) 2025/2392. Pick one. Anything else is a default product.

Closest category Annex III, Annex IV
What tamper resistance is the chip designed to? 2025/2392; Common Criteria AVA_VAN

The designed vulnerability-assurance level separates Class I, Class II and the Annex IV secure elements.

How clear is the match?
Integration does not reclassify the host. Embedding an operating system or a VPN module does not make a phone an OS or a VPN (Art 7(1); guidance Example 58). Ancillary features do not declassify. A router with firewall functions is still a router. Modules sold separately are separate products. A suite's SIEM module sold on its own is Class I; its IDS module Class II (guidance para 145). Marketing does not decide it. The test is objective (para 142), and wrong route choice can be fined under Art 64(3).
3

Anything that changes the route?

Two overlays can change the conformity procedure, and market timing decides which units need it.
