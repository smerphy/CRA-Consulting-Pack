Data protection and integrity. Item (e): TLS 1.3 or equivalent, mutual authentication on machine-to-machine links, no plaintext fallback, and data at rest encrypted with keys held in a secure element, TEE or key-management service. Keep a cryptographic inventory against a published catalogue. Item (f): verified boot from a root of trust, signed firmware and configuration, authenticated commands, and a logged or visible event when corruption is detected; silent repair is not enough. Item (g): collect only what each function needs, keep telemetry off by default with opt-in, and enforce retention in code rather than in policy. Item (k): use memory-safe languages for new code where possible; otherwise harden the build, sandbox parsers and verify the flags on the shipped binary. The T200 shows the pattern: presence data stays on the device, the cloud sees setpoints only, and signed commands with a nonce defeat replay.
