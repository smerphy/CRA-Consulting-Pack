Illustrative · 10

The release security gate is where design meets evidence. It runs before tagging any release and checks four things: the build was reviewed and tested; the supply chain is clean, meaning a signed SBOM and a known-exploitable check; the shipped configuration is secure and the update is signed with its rollback counter raised; and the market decisions are made: whether this is a substantial modification, what documentation changes, and whether the existing declaration still covers it. The output is the gate record, a structured file committed with the release tag and signed by the release manager and the product security owner. The implementation guide calls it the single most useful artefact in the file, because it ties a shipped artefact to its tests, SBOM and decisions. Status: the gate is designed but not yet enforced, and the T200 is the pilot product.
